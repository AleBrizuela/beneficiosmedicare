## What actually happened, in order

1. Found the real structure was **three header families**, not one: a `t31` home-page system
   (`index.html`, `en.html`), a hybrid `sm-header`-wrapper-with-`t31`-controls "key page" system
   (`beneficios/contacto/privacidad` ES + `benefits/contact/privacy` EN, **plus 8 BM-only Spanish
   pillar guides that share the same design** — not in the ticket's own page list, found by the
   stamp script's first dry run), and a plain `sm-header` system (the other ~96 pages). Only the
   plain and key families were brought under shared partials this pass; the two `t31` home pages
   and the two `presentacion`/`presentation` partner pages (different `topbar` design, approved
   exception per CLAUDE.md) are untouched, logged, and need their own pass.
2. Built partials for header (4 variants: plain×{es,en}, key×{es,en}), footer (2: es, en),
   head (favicon ×2 variants, font ×2 variants, GA4), logo, and a reference `brand-tokens.css`.
3. Built `tools/stamp-shared.mjs`: a page only gets wrapped in `<!-- shared:X -->` markers the
   first time if its current content is byte-identical (or, for favicon/font, whitespace-
   identical) to a known canonical variant — it is never rewritten to different content. Once
   marked, later runs re-sync it to whatever the partial currently says, which is how "edit one
   file, run the script" actually works. Both properties — safe first entry, real propagation —
   were tested directly, not assumed (see the old-logo-check report).
4. **Caught and reverted a real bug before committing it**: a first attempt also replaced exact
   hex matches inside every page's own inline `<style>` with `var(--name)`. This is unsafe here —
   `widget-v4.html` (the plan-finder widget, on the lead path) already defines its OWN `--teal`,
   `--navy`, `--gray` with DIFFERENT values than brand.css (its `--teal` is `#00897B`, the retired
   Material teal CLAUDE.md warns about), so the substitution would have silently changed the
   widget's rendered colors. Worse, an early version even rewrote inside a page's own `:root`
   line, turning `--navy:#002147` into the circular, broken `--navy:var(--navy)`. Fully reverted
   (nothing was committed in that state); color-token substitution is OUT of this pass, audit-only.
5. Found `partials/*.html` would be served as orphan fragment pages once pushed (CLAUDE.md's
   "repo-root files are public" problem, one directory deeper) and that `site-check.py` was
   scanning them as if they were real pages (17 errors/76 warnings vs the true 1/22 baseline).
   Added `partials` to the gate's existing `SKIP_DIRS` set (same pattern already used for
   `tools/`). Gate is now identical to `origin/production`: 1 error, 22 warnings.
   **`partials/` is NOT yet blocked in `_redirects` — it will be publicly servable once pushed.**
   Flagging rather than touching `_redirects` without asking (ship skill hard rule).
